# Журнал ошибок и карта зон роста (.NET Backend)

Документ фиксирует инженерные, архитектурные и стилистические ошибки, допущенные в процессе выполнения проектов.
Служит обязательным чек-листом для самопроверки разработчиком и входной точкой для код-ревьюера перед оценкой любого PR.

---

## 1. Предполетный чек-лист перед ревью (Pre-Flight Checklist)

Пройдись по списку **до** отправки кода на проверку или создания PR:

- [ ] **Архитектура & SRP:** Бизнес-логика, валидаторы и расчеты не вызывают `Console.*` (I/O полностью изолирован в `Program.cs` / слое представления).
- [ ] **Чистота функций:** Методы валидации и расчетов возвращают новые результаты (`ValidationResult`), а не мутируют переданные снаружи коллекции (`List.Add`).
- [ ] **Изоляция доменных моделей:** Сущности не содержат захардкоженных зависимостей от других сущностей (деталь не знает о размерах коробки).
- [ ] **Соглашения по именованию (C# Naming):**
  - Все публичные члены, классы, методы, свойства и позиционные параметры `record` / `record struct` названы строго в `PascalCase`.
  - Отсутствуют опечатки в именах (`Height`, а не `Heith` / `Heigth`).
- [ ] **Надежность ввода:**
  - Строки валидируются через `string.IsNullOrWhiteSpace`.
  - Числа парсятся с учетом культуры (`CultureInfo.CurrentCulture`) и проверяются на положительные значения (`> 0`).
- [ ] **Культура Git:** Коммиты оформлены строго по `Conventional Commits` (`feat:`, `fix:`, `refactor:`, `style:`).

## 2. Зона особого внимания (Watchlist: частые рецидивы)

Здесь зафиксированы грабли, на которые наступали 2+ раза. Требуют пристального внимания при написании нового кода.

### 🔴 Рецидив 1: Нарушение регистра в параметрах `record` (camelCase вместо PascalCase)
- **Где повторялось:** Задача 1 (`GetProductInfo`), Задача 2 (`HandleItem`, `ExceedanceInfo`).
- **Суть проблемы:** Позиционные параметры рекорда в C# компилируются компилятором в **публичные свойства** `{ get; init; }`.
- **Правило:** Публичные члены в C# обязаны быть в `PascalCase`:
  ```csharp
  // ПЛОХО:
  public sealed record ExceedanceInfo(string name, double itemsize, double limit);
  // ХОРОШО:
  public sealed record ExceedanceInfo(string Name, double ItemSize, double Limit);
  ```

### 🔴 Рецидив 2: Утечка оркестрации в классы представления (Нарушение SRP)
- **Где повторялось:** Задача 1 (`CalculateProductPrice`), Задача 2 (`PackageDimensionsPrinter`).
- **Суть проблемы:** Принтер брал на себя опрос клавиш (`Console.ReadKey()`), принятие решений и повторный вызов бизнес-логики (`DimensionsValidator.RotateTry`).
- **Правило:** Принтер только форматирует и выводит данные (метод `void`). Вся оркестрация сценария (задать вопрос -> получить ответ -> вызвать сервис -> передать результат принтеру) выполняется исключительно в точке входа (`Program.cs`) или Application-сервисе.

## 3. База знаний и закрытые темы (Resolved Knowledge Base)

### Микропроект 2: PackageDimensionsValidator (Валидатор упаковки и укладки)

| Ошибка | Как было | Как решено | Чем грозило в продакшене |
| :--- | :--- | :--- | :--- |
| **Смешивание сущностей в модели** | Размеры коробки (`BoxLength`, `BoxWidth`) зашиты константами внутри `HandleItem`. | Создана универсальная структура `Dimensions`, деталь и коробка передаются раздельно. | Жесткое зацепление (tight coupling). Невозможность сменить коробку или поддержать несколько типов тары на складе. |
| **Мутация входного списка в валидаторе** | `ValidateDimensions(handle, List<ExceedanceInfo> list)` наполнял чужой список. | Метод возвращает объект `ValidationResult(bool IsFit, IReadOnlyList<ExceedanceInfo> Exceedances)`. | Побочные эффекты, риск передачи замусоренного списка, невозможность параллельного вызова в многопоточной среде. |
| **Логический нонсенс при повороте** | Метод поворота одновременно поворачивал и деталь, и коробку, выводя пользователю искаженные размеры тары. | Коробка зафиксирована. Поворачивается только деталь; метод `ValidateWithRotation` возвращает честный `ValidationResult`. | Логический баг в складской системе (виртуальное изменение физических размеров тары). |
| **Избыточный boolean if/else** | `if (exceedances is []) return new ValidationResult(true, ...); else return new ValidationResult(false, ...);` | `return new ValidationResult(exceedances.Count == 0, exceedances);` | Раздувание кодовой базы, снижение читаемости. |
| **Несоответствие типов** | Размеры описывались через тяжелые классы. | Введена `readonly record struct Dimensions`. | Избыточные аллокации в куче (Heap) и лишняя нагрузка на сборщик мусора (GC). |

### Микропроект 1: ProductOperations (Расчет стоимости и НДС)

| Ошибка | Как было | Как решено | Чем грозило в продакшене |
| :--- | :--- | :--- | :--- |
| **Глобальное изменяемое состояние** | `public static string Article;` в теле класса. | Отказ от статических полей состояния, переход на `record Order(...)`. | Race Condition в многопоточном сервисе (ASP.NET Core) — данные пользователей перезаписывали бы друг друга. |
| **Класс-пустышка (Fake Wrapper)** | `PriceCalculator.Order` внутри вспомогательного класса. | Сущность вынесена в самостоятельный файл `Order.cs`. | Загромождение иерархии типов, сложность навигации по проекту. |
| **Расхождение баланса налога** | Раздельный независимый расчет `Subtotal * 0.16` и `Subtotal * 1.16`. | `TotalPrice => Subtotal + VatAmount`. | Накопление погрешности округления: `Итог != База + Налог` (аудиторская ошибка). |
| **Погрешность копеек/тиынов** | Округление без явного указания режима. | Использован `MidpointRounding.AwayFromZero`. | Потеря долей центов/копеек при массовых операциях. |
| **Сбой булевой проверки ввода** | Ошибка в условии валидации типов (`&&` вместо `\|\|`). | Исправлено в `InputHelper.Prompt<T>`. | Пропуск некорректных значений в доменную модель. |
| **Игнорирование локали** | Парсинг зависел от настроек ОС без явной культуры. | Явная передача `CultureInfo.CurrentCulture`. | Падение парсера чисел с плавающей точкой на серверах с другой локалью. |

### Микропроект 3: TieredPriceCalculator (Модуль оптового ценообразования)

| Ошибка | Как было | Как решено | Чем грозило в продакшене |
| :--- | :--- | :--- | :--- |
| **Сложение денег со ставкой (%)** | `discountRate += CalculateProgressiveDiscount(...)` прибавляло сумму в рублях к процентной ставке. | Разделены понятия процентной ставки (`Rate`) и суммы скидки (`Amount`). Модели согласованы. | Полный слом финансовой логики, скидка срезалась лимитом 25% на любые объемы. |
| **Баланс с обратным знаком** | `TotalPrice => Subtotal + DiscoutAmount`. | `TotalPrice = Subtotal - DiscountAmount`. | Финансовый абсурд: предоставление скидки увеличивало итоговый счет покупателя. |
| **Накопление вместо выбора порога** | В цикле плоской скидки суммировались все ставки (`0.18 + 0.10 + 0.05`). | Возвращен `switch expression` с relational patterns. | Неправомерное завышение скидки покупателю (33% вместо 18%). |
| **Инвертированный поиск аномалии** | Поиск границы в отсортированном по убыванию массиве находил порог 500 вместо 50 для 48 шт. | Массив отсортирован по возрастанию, либо используется проверка диапазонов. | Логический баг бизнес-советника (предложение купить 500 шт вместо 50). |
| **I/O в доменном сервисе (SRP)** | Метод валидации промокода писал ошибки напрямую в `Console.WriteLine`. | Консольный вывод удален, калькулятор является чистой детерминированной функцией. | Невозможность переиспользования в Web API/ботах, мусор в логах сервера. |
| **Опечатки в публичных контрактах** | `DiscoutRate`, `DiscoutAmount` (пропущена буква `n`). | Исправлено на `DiscountRate`, `DiscountAmount`. | Нарушение контракта API, поломка клиентов при сериализации/интеграции. |
| **Скрытие бага через default-параметр** | `CheckWholesaleAnomaly(quantity)` вызвался без `customerTier`, сработало тихое `= Retail`. | Убран опасный дефолт, аргумент сделан обязательным при вызове из `Program`. | Несоответствие расчетов: оптовика проверяли по розничной сетке. |
| **Файл-свалка (Objects.cs)** | Смешивание нескольких разнородных типов (`CustomerTier`, `PricingResult`) в одном файле `Objects.cs`. | Разделено по правилу: 1 публичный тип = 1 файл с соответствующим именем. | Запутывание структуры проекта, плохая читаемость и поиск в кодовой базе. |
